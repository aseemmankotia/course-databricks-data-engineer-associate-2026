## Chapter 11: Unity Catalog Governance and Security — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the three levels in Unity Catalog's namespace? | catalog.schema.table — catalog is the top data container, schema (aka database) groups tables, table is the leaf object. Exam tip: the metastore sits ABOVE catalog and is NOT part of the 3-part name. |
| 2 | What is the top-level governance container in Unity Catalog? | The metastore. It holds catalogs and is assigned to one or more workspaces. Exam tip: privileges are stored at the metastore level, so grants apply across every attached workspace. |
| 3 | Function used inside a dynamic view to check group membership for row/column security? | is_account_group_member('group_name') — returns TRUE if the querying user belongs to that account-level group. Exam tip: the older is_member() checks workspace-local groups and is not the current recommended function for UC. |
| 4 | SQL pattern for row-level security in Unity Catalog? | CREATE VIEW v AS SELECT * FROM t WHERE is_account_group_member('region_east') OR region = current_user(); then grant SELECT on the VIEW, not the base table. Exam tip: users always query the view, never the underlying table directly. |
| 5 | SQL pattern for column masking in Unity Catalog? | CASE WHEN is_account_group_member('hr') THEN ssn ELSE 'REDACTED' END AS ssn inside a view definition. Exam tip: masking is implemented via dynamic views, not via column-level GRANT statements. |
| 6 | What does the Unity Catalog lineage graph automatically capture? | Table- and column-level upstream/downstream dependencies across notebooks, jobs, DLT pipelines, and dashboards — captured automatically, no extra config needed. Exam tip: used for impact analysis and debugging data flow. |
| 7 | What two objects are required to let Unity Catalog access an external cloud storage path? | A STORAGE CREDENTIAL (wraps the cloud IAM role/service principal) and an EXTERNAL LOCATION (registers the storage path and references the credential). Exam tip: create the storage credential FIRST. |
| 8 | Basic GRANT syntax in Unity Catalog SQL? | GRANT <privilege> ON <securable_type> <securable_name> TO <principal>; e.g., GRANT SELECT ON TABLE main.sales.orders TO analysts; Exam tip: the inverse is REVOKE <privilege> ON ... FROM <principal>. |
| 9 | Privilege needed just to 'see' and browse a catalog before querying its tables? | USE CATALOG — followed by USE SCHEMA on the schema, then SELECT on the table. Exam tip: 'USAGE' is a Snowflake term and is NOT a valid Unity Catalog privilege name. |
| 10 | Key difference: Legacy Hive metastore table ACLs vs Unity Catalog access control? | Legacy ACLs are workspace-scoped with no lineage or masking support. Unity Catalog is account-level/centralized, works across all attached workspaces, and includes automatic lineage plus dynamic-view row/column security. Exam tip: UC grants stored at the metastore level apply to every attached workspace instantly. |
| 11 | Does granting a privilege at the schema level cascade to tables inside it? | Yes — GRANT SELECT ON SCHEMA catalog.schema TO group grants SELECT on all current AND future tables in that schema (privilege inheritance). Exam tip: inheritance flows downward: metastore → catalog → schema → table. |
| 12 | Where do you view the Unity Catalog lineage graph in the UI? | Catalog Explorer → select a table or column → 'Lineage' tab, showing the upstream/downstream dependency graph. Exam tip: don't confuse with DESCRIBE HISTORY, which only shows one table's version history, not cross-object dependencies. |
